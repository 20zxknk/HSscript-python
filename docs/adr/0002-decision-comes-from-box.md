# 决策：决策完全交给盒子，不自研战术

Status: implemented

## 问题

脚本要知道“这一回合该干什么”，有两条路：自己做 MCTS / 规则引擎，或者用网易盒子算好
的推荐。前者要在脚本里实现出牌序、斩杀线、解场优先级，还要跟着每个版本的卡池和环境
调整；后者是别人已经算完的一段字符串，我们只要读出来。

另外还有一个更隐蔽的成本：自己算的战术一旦打错，日志里分不清是“判断错”还是“执行错”。

## 决定

用盒子的推荐，脚本里不写任何战术判断——不出牌序、不算斩杀、不猜对手手牌。
`src/hspy/decision/` 只做一件事：把推荐翻译成 `Plan`（动作、卡、槽位、目标）。

## 后果

责任变得可归因：打错了是盒子给错，执行错了是我们的 bug，两者在日志里能分开。
维护成本也压到最低：环境变了只要盒子更新，我们不需要改判断逻辑。

代价同样明确。盒子挂了、或者它换了版本换了实现，桥就跟着失效——桥是 frida 钩在它的
Qt 字符串层上，那一层不是公开接口。脚本也因此没有任何兜底策略：盒子沉默时它只会等。

**没选的路**：自己写规则引擎，能摆脱外部依赖，但要把整套卡组/斩杀/解场判断重写一遍，
成本等于再造一个盒子，而且效果大概率更差——盒子的模型是拿真实对局数据训的。
