# 坐标表

所有坐标都是作者的相对值：横轴按 `real_h * CONTENT_RATIO` 缩放、以内容区中心为原点，
再由 [`GameRect.relative()`](types.md) 换算成客户区像素。下面几张表**与源码逐字一致**，
由 [`scripts/verify_type_equiv.py`](../../scripts/verify_type_equiv.py) 校验。

为什么不能自己改表：曾经用“点不中就 ±130 试探、成功就记住”的补偿把作者的表覆盖坏，
结果 4 候选面板必选错（见 [0004](../adr/0004-use-authors-native-mouse.md)）。

## 内容区宽度系数

游戏按高度等比渲染、两侧留边，所以横轴要用 `real_h * CONTENT_RATIO` 而不是客户区真实宽度。
按真实宽度算会把整排矩形拉宽。

具体像素值**不写死**，因为随窗口尺寸变。要用的时候算一句：

```powershell
python -X utf8 -c "import sys; sys.path.insert(0,'src'); from hspy import coords; \
print([r.relative(1905,982)[0] + r.relative(1905,982)[2]//2 for r in coords.MY_HAND[5]])"
```

1905×982 时 6 张手牌的牌心是 `700, 783, 856, 932, 1013, 1115`（跨度 415px，内容宽 1327px）。
