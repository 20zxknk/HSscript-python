# 14 主菜单被「赛事中心」弹窗挡住时，导航只会在 HUB 上空点到超时

**状态：已修**

## 现象

导航看到 `mode=HUB`，就一直点「传统对战」，但屏幕被一个弹窗盖住：

```
[nav] go_tournament: mode=HUB 第1次 seq_done=False (剩 240s)
[nav] HUB 卡住 4 次（这个界面没有可点的返回，继续等）
[nav] go_tournament: mode=HUB 第9次 seq_done=False (剩 201s)
... 一直到 第25次
```

240 秒全花在空点上，一局都没进。

## 触发条件

主菜单上盖着「赛事中心」弹窗（截图为证）。点「传统对战」的坐标完全落在弹窗区域里，
所以每次点击都没效果；导航的 `HUB` 分支只会点 `coords.TOURNAMENT_MODE`，
没有「先识别并关掉弹窗」这一步。

## 触发场景

2026-10-27 10:58–11:00 `test/v5`。手动在客户区 `(72%, 22%)` 点一下「关闭」，
弹窗消失、回到正常主菜单（截图已删除）。

## 日志文件（原始文件，直接放在本目录 `logs/` 下）

- `logs/run-v5-hub-stuck.log`
- `logs/SOURCES.txt`

## 根因

导航只按 `screen` 报出来的 `mode` 决策（`HUB`），但弹窗不会改变 `mode`——
屏幕还是 HUB，只是被覆盖层挡住。当前代码里没有任何“弹窗/覆盖层”识别。

## 修复（未开始）

两个方向，都应该先有证据再改：

1. 识别弹窗：切图/像素特征（弹窗顶部有金色边框和「关闭」按钮），或者用盒子/游戏自己的界面日志；
2. 兜底策略：`HUB` + 连续 N 次点击后 `seq` 没变化 → 点一次弹窗关闭位置（客户区 `(72%, 22%)`），
   再重新判断——这条要用真实日志验证不会误点。

注意：这条不能简单用「点一次关闭」当兜底，先要确认弹窗只在这个位置出现。

## 修复（2026-10-27 18:40）

覆盖层的判据是**米色占比**，不需要 OCR、不需要模板文件：

```python
# src/hspy/overlays.py
BEIGE_BOX = (0.25, 0.25, 0.75, 0.75)   # 画面中央
BEIGE_MIN = 0.15                       # 实测：弹窗 0.50+，正常主菜单 0.002

def tournament_modal_open(img) -> bool:
    return beige_ratio(img) >= BEIGE_MIN
```

导航在 `HUB` 分支里先看一眼画面：是弹窗就点「关闭」（客户区 `(0.72, 0.22)`），
关掉之后照常点「传统对战」；不是弹窗就直接点。见 `navigator.close_overlay()`。

两条实测（同一台机器、同一分辨率 1905×982）：

```
赛事中心弹窗     米色占比 0.520   -> 判为覆盖层
正常主菜单       米色占比 0.002   -> 不误判
```
