# 09 客户端掉线弹「重新连接」时，导航不认识这个弹窗，只会在底部空点到超时

**状态：未修**

## 现象

挂机一段时间没操作，客户端弹出一个居中对话框：

```
重新连接
当前处于离线状态
距离你的上一次操作已经过了很长时间，游戏连接中断。
[重新连接]  [取消]
```

这时 `run.py` 的 `to_hub()` 只看到 `mode=GAMEPLAY`，就按「结算界面」分支反复点
`click_ratio(0.50, 0.93)`（客户区 (952,913)，屏幕最底部中间），而对话框的两个按钮在
客户区约 `(760,724)` / `(1070,724)`——**点了 33 次一次都没落在按钮上**，直到 120 秒超时退出。

## 触发条件

1. 客户端因长时间无操作被服务器断开（游戏自己弹「当前处于离线状态」）；
2. 此时跑 `run.py`：`mode` 仍是 `GAMEPLAY`，`st.finished / st.started` 判定不出弹窗；
3. `navigator.to_hub()` 走 `GAMEPLAY` 分支 → 点底部 → 无效 → 每 0.8 秒重试 → 超时。

## 触发场景

2026-10-26 20:58:56 起的实验 B（`logs/run-expB-nav-loop.log`）：

```
[run] 进对局前界面: mode=GAMEPLAY
[nav] to_hub: mode=GAMEPLAY 第1次 (剩 120s)
[nav] 对局已结束，点「点击继续」离开结算界面     ← 连打 8 次
[nav] to_hub: mode=GAMEPLAY 第9次 (剩 97s)
... 一直到 第33次 (剩 27s)，共 33 次点击，界面毫无变化
```

同一时刻的屏幕（截图已删除）：屏幕上是「重新连接」对话框，
不是结算界面。手动在客户区 `(760,724)` 点一下「重新连接」，6 秒后回到主菜单
（截图已删除）。

## 日志文件（原始文件，直接放在本目录 `logs/` 下）

- `logs/run-expB-nav-loop.log`（第 23–68 行是这 33 次空点）
- `logs/SOURCES.txt`：以上文件各自的原始路径

## 根因

`navigator.to_hub()` 的 `GAMEPLAY` 分支只看 `st.finished or not st.started`，
无法区分「结算界面」与「掉线重连弹窗」；两者的按钮位置完全不同，
而它只会点固定比例 `(0.50, 0.93)`。

## 修复（未开始）

两个方向，待定：

1. **识别弹窗**：按 `Screen.log` / 窗口特征判断「重新连接」对话框，点 `(0.50, 0.74)`；
2. **换判据**：`GAMEPLAY` + `st.started` 但日志长时间没有任何 STEP/TAG 变化时，
   先点「重新连接」的固定位置，而不是底部。

补丁必须带一条可核对的证据：修完之后同一份 `logs/run-expB-nav-loop.log` 场景下，
点击应当落在 (760,724) 并离开弹窗。
